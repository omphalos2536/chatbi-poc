## 影响验收的风险与处置

| 风险或待核事项 | 实施判断和验证责任 |
|---|---|
| 内存余量随其他任务变化，实际 RSS 和全套时延未测 | dsh 在 03/05 记录解析峰值（可用 /usr/bin/time -v，如不可用则采样进程 VmHWM）、耗时和工作集。合并区按区间索引，逐表处理；资源紧张时串行重跑。RAGFlow、向量模型和 OCR 留待有足够内存的环境。[RAGFlow 起步要求](https://ragflow.io/docs/) |
| 包版本、沙箱或系统库变动 | 固定 PG 包 SHA 和 uv.lock；下载失败可用已核验的本地缓存。不同机器先测试 initdb、启动、扩展和真实 PG 权限。若不支持用户命名空间，改用管理员配置的独立服务账户/文件 ACL 与出口隔离，仍以相同探针验收 |
| 单元格存在格式噪声或披露精度有限 | 导入者签认单位、零/空、比率规则、服务分类。采购万元已舍入，缺单价按缺失记录，禁止倒推虚假单价。报表中的区间、快报、年度期初与季度期初保留来源。汇总 KPI 与明细口径冲突时记录两者，验收者按原表复核 |
| 工作簿与概述有出入 | 产品主数据没有“是否服务”专列；维修/延保和同大类实物配件应在 06 分类确认。部分客诉受理日期早于季度、应收发票可来自期前；区分台账覆盖和事件发生期。工作表维度、缓存及范围变化触发重新盘点 |
| 关键数字需要业务决定 | 选取收入、成本、毛利额、毛利率、合格产量、一次合格率六个 POC 候选；按工作簿将销售净额作为本期不含税收入，以报工实际数作合格率分母。正式客户应复签。应收快照无法完整复原按收款日发生的流水 |
| 模型行为波动和 API 故障 | 02 最小实连、12 单题实连、15 整批验证，保存模型名、请求时间和重试次数。缺密钥时继续假传输、清洗和签字模板测试，真实项目标 PENDING。固定超时、串行预算和错误分类，留存原始失败，不以挑选轮次提高成绩 |
| 评测基准泄漏或精度不明 | 运行包、挂载和网络按白名单构建；基准只归评分器/验收者。评分断言冻结，部分表格仅列部分名次时，先独立补证并记录。参考的 validation_report.json 未在资料中发现，使用工作簿公式自建勾稽报告 |
| 数据域与云出口不一致 | 财务、销售、生产及诊断分级示范，云端仅可见脱敏问题及批准字典。实施时独立检查实际请求和 PG GRANT，回归来源链接和撤权。正式机房另核模型供应商协议、真实权限矩阵及网络策略 |
| POC 工作量与上线条件 | 各步估算为编码与单步测试时间，人工签认、真实模型耗时和返工按实际记录。并发性能、真实客户数据准确率、OCR 发布能力与生产鉴权均需另行实测；本次模拟得分仅描述冻结批次 |

PG 的只读事务、库权限与 SQL 解析器为实施基线。下载成功和库可导入只验证环境，完整应用效果须按[验收规范](验收规范.md)核验。[PostgreSQL 事务](https://www.postgresql.org/docs/17/sql-set-transaction.html) · [PostgreSQL 权限](https://www.postgresql.org/docs/17/ddl-priv.html) · [SQLGlot](https://sqlglot.com/sqlglot.html) · [openpyxl 只读模式](https://openpyxl.readthedocs.io/en/stable/optimized.html)
