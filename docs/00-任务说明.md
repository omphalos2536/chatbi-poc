## 背景
我们（OPC 公司，2 人）要给一家 MLCC 检测治具厂做“企业知识库 + 问数”，预算约 10 万。架构结论见 refs/Codex架构评审报告.md（窄范围版：RAGFlow 管文档、PostgreSQL 管数字、签字指标走参数化 SQL 模板、长尾走模型生成 SQL 并本地校验、导入时做字段映射、统一自建 BFF+界面、唯一云出口）。问数实现借鉴 refs/Text2SQL与SQLBot实现原理.md（术语库、示例 SQL、按相关度挑表、sqlglot 白名单/只读校验，补齐自动纠错重试 2–3 次与权限）。

现在先在这台测试机上做一个 **问数 POC**，用一份虚拟制造业数据检验效果：

- 评测基准：refs/答案基准与清洗规则.md（40 道标准答案 + 陷阱清单 + 评分建议）。**这份文件只给评测脚本和验收者用，被测系统（提示词、术语库、示例 SQL、运行时上下文）绝不能读取或包含其中的答案**；可以参考其数据字典/陷阱清单来设计清洗规则，但不能把标准答案写进模板或示例。工作簿里自带的「数据字典与口径」工作表可以给系统用。

## 分工（重要）
- 你（Codex）只写文档：架构、分步计划、每一步的详细执行说明和验收条件。**不要写任何项目代码**（文档中可以有接口定义、表结构、伪代码、命令示例）。
- 所有代码由 dsh（一个便宜的编码 agent，支持多 agent 并行）按你的文档逐步完成。它能力中等，所以每步说明要具体、可执行、无歧义，指明文件路径、目录结构、技术选型和版本。
- 每步完成后由另一个模型按该步验收条件验收，所以验收条件必须**可客观判定**：可运行的命令、期望输出、数值阈值、要检查的文件。

## 测试机环境（请自己用命令核实）

- 已有 Node v24、Python 3.13。可联网安装 pip/npm 包（可能需要你核实 PostgreSQL 能否用 apt 或其他方式装）。
- RAGFlow 官方建议 16GB 内存，这台机器大概率跑不动：POC 的问资料部分如需要，请给出轻量替代或明确放到后续步骤，以问数为主。
- 运行时大模型：OpenAI 兼容接口，base_url `https://api3.kkyy.site/v1`，模型 `deepseek-v4.1-flash`（便宜），API key 由环境变量 `CHATBI_LLM_API_KEY` 提供（文档中只写变量名，不写真实 key）。数据是虚拟的，可以发到云端，但架构上仍要保留“只把问题和授权字典发给云端”的设计，便于以后换成真实客户数据。
