# 问数 POC 验收规范

本规范供独立验收者使用。文档交付时只有设计与计划；以下命令供 dsh 完成对应步骤后执行。步骤 01 建环境，其余步骤默认在项目根使用 `source .venv/bin/activate`。每步的输入、文件名、命令和通过标准从[总体设计中的步骤索引](01-总体设计.md)进入。

## 每步怎样验

1. 按依赖表领取步骤。取得锁文件/构建摘要、测试用例、所需夹具和上游步骤结果。记录机器、执行人、时间、书簿 SHA、数据库版本、运行资产和配置摘要。没有 Git 时对相对路径排序后的发布文件逐一计算 SHA-256，再对清单计算哈希。
2. 在独立测试库做修改数据、失败、重试、并发和权限试验；真实工作簿始终只读。核对该步的交付物逐项存在，运行每条编号验收命令，记录实际命令、退出码、输出摘要及 JSON/截图。验收者要读测试断言并独立选一条正例和一条负例复验；`pytest -k` 选中 0 项、skip 或 xfail 均不能证明该项通过。
3. 每步存 `var/evidence/step-NN.json`，含 build_sha、batch_id、operator、timestamp、case_id、command、exit_code、expected、observed、artifact、status。评测侧含预期值的证据改存 `private-eval/`；对外清单只放摘要和私有附件 ID。安装步骤以环境摘要代替尚不存在的批次号。
4. 单条证据满足规则记 PASS；命令/断言不符记 FAIL；缺所需凭据、真实请求或人工确认记 PENDING 并写明缺项。步骤全部必验条通过才算通过。可并行开发或用 mock 做离线验收；需要真实 PG、真实模型或人工签认的条目单独收证，没有证据的条目保留待验。修复后复跑原失败项、所属步骤和受影响下游，保留首跑记录。

| 检查点 | 验收者独立核对 |
|---|---|
| 01–04 环境、盘点、映射 | PG 确实接受连接；28 张表逐项匹配原名；改一个待审列的单位，确认旧版本失效 |
| 05–08 计算输入 | 追一条退货和一组合并维度回 Excel，核一笔万元换元；按左右来源重算一个勾稽；制造不平衡时线上批次不变 |
| 09–13 查询 | 同义问法命中同模板；检查数据库 actual user 与读取权限；记录每次纠错发出的字段；对选中子问逐项核对 |
| 14 交互 | 从页面发问、查看参数、定位实际工作表，换身份访问相同 source_id 验权限 |
| 15–16 验收 | 冻结包后在隔离进程串行跑 40 题，保存首轮结果和每一处失败；按批次重放一次回答 |

## 评测隔离和可复现性

验收者单独维护基准、私有断言和报告。给运行系统的输入只有逐题题干；去掉题号和评审标签。评测账号的授权决定可用字典。批准上云的元数据、提示、示例、模板、索引、缓存和 UI 资源要列入发布清单。由验收者对准许来源、打包清单与实际运行挂载交叉核对。抽取私有基准特有的完整答案片段及唯一哨兵检查运行资产和捕获的合成请求；数字巧合需逐项溯源，单纯全文搜索不足以证明隔离。被测服务按同一运行配置尝试打开约定的禁读路径应全部失败，结果记录在隔离报告。屏蔽评测后临时文件、生成报告和目录符号链接等间接路径。

用于校验网关的明文载荷捕获只用自编合成数据。实测保留目的主机、payload 键、字典摘要、模型和 request_id，标准答案及结果表不能进入请求。评分器不调用云模型做裁判。实现 `evaluator audit` 时核对每题 question 哈希、会话隔离、问答时刻对应的运行包摘要和网关调用；扫描/探针失败保留具体证据。疑似泄题时冻结该次成绩，修正打包与挂载后在新构建重新验收。

## 40 题怎么算分

题组按 Q1–20 基础、Q21–32 分析、Q33–40 陷阱固定。按题干的必答项逐个比对实体、期间、粒度、单位、数值和原因，金额绝对误差 ≤1 元，比率绝对误差 ≤0.01 个百分点。完整算法、精度不足或基准部分缺项的处理见[隔离评测](steps/step-15-隔离评测.md)。验收者先完成断言与补证，再冻结，所有题均有终态。报告输出五维分、每组正确数、逐项偏差、HTTP/模型失败、review 项的证据；人工裁定不得改写原始响应。

| 维度 | 满分 | 可观察证据 |
|---|---:|---|
| 口径正确性 | 35 | 税、期间、净额/原值、分母、过滤及定义 |
| 数据清洗 | 30 | 合并补齐、行分类、文本解析、换算与可追溯诊断 |
| 结果准确性 | 20 | 分组键、排名、符号、计数及金额/比率容差 |
| 勾稽验证意识 | 10 | 同一批次的实际检查 ID、双方来源和核对结论 |
| 解释与洞察 | 5 | 依据、方向、异常与假设标签；空泛判断不得分 |

采用基准的 A/B/C/D 分级含义，以下数值线是本 POC 为可执行验收补定的门槛。自上而下判定，分数比较用未舍入值。

| 等级 | 判定条件 |
|---|---|
| A 优秀 | 基础 20/20，分析 12/12，陷阱 8/8，口径及勾稽各维适用断言全过 |
| B 良好 | 基础 20/20，分析至少 8/12，陷阱至少 6/8，五维总分 ≥80 |
| C 基本可用 | 未达 A/B，能定位表头并复算合计，基础至少 15/20 |
| D 不合格 | 其余情况，包括无法定位表头或给出可核对的合计 |

**最终通过条件**为 A 或 B 且总分 ≥80，并满足下列硬门槛。C 表示已有基本能力，按本轮演示验收记未通过。分级、总分和硬门槛分别列示。

1. 28 表处置完整，发布批次必检勾稽缺失或失败数为 0。模板 6/6 有审批，12/12 同义问法走签字 SQL。任一失败或审批缺失的批次/模板不得用于演示。
2. 越权读取、未批准语句送执行、非法外发、基准进入运行资产任一确认即失败。个人令牌、PG 写权限和云密钥按角色隔离。
3. 真实模型至少成功回答一条自编长尾并提供可复算结果。自动纠错达到步骤 12 的独立验收条件。整套 40 题用同一构建、同一批次和指定真实模型配置，40/40 有终态，私有报告、网页复算与源行证据可查。
4. 步骤 01–16 的必验项无 FAIL/PENDING，评分有争议的必答项全部裁定。外部服务不可用可另约时间复验，期间整体状态为待验证。

## 如何写问题清单

一个问题一条，使用 `NN-序号` 标识。字段为步骤/验收条号、构建与规则哈希、批次/身份、触发条件、最短复现命令、期望、实际、影响、证据路径、负责人、修复期限、回归范围和复验结论。P0 用于越权/泄题/未核批次发布，P1 用于结果错误、无法复算或核心流程中断，P2 用于显示及说明偏差。评测题的数值证据仅保留于私有附件。跨步骤问题在一个主单上记录所有受影响门槛。

例：`08-01｜S08.2｜合成库｜pytest -q tests/test_s08.py -k mismatch｜期望发布指针不变｜实际指向失败批｜P0｜证据 var/evidence/check-switch.json｜回归 07、08、14、16`。修复者交回新构建标识、根因、修改文件及原复现的输出，验收者独立重跑并署名关闭。
