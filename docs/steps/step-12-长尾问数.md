# 12 长尾问数

## 目标

让模型为字典范围内的长尾问题产生 SQL，自动纠错后在本地返回可核对的结果。

## 前置条件

02、08、09、10 已就绪，单步测试可替换传输层。

## 输入

脱敏问句、授权后的检索结果、源关系和本地参数、只读执行器。

## 详细任务清单

1. 固定流程：解析意图及期间 → 挑获准视图/列、术语和无值示例 → 02 发送最小字典 → 解析单个 JSON（sql、必要参数名、输出列及单位声明）→ 10 校验 → 本地绑定、执行 → 用本地目录核对单位、来源并生成结果块。模型无数据库接口；结果解释不再调用模型。选择不到充分来源时返回 clarify 或 unsupported。
2. 每块初次生成后**最多自动纠错两次**（总调用 ≤3），全程自动。JSON 格式、可修正的语法、未知列拼写、分组或类型错误映射为本地枚举；重检原授权字典后再发原脱敏问题，用固定 system 提示指出错误类别和修正要求。上次 SQL、错误细节、结果值不出域。越权、非查询、受限域和重复失败的同一候选立即停止。模型 401/403、缺密钥直接 unavailable；429/暂时性 5xx 或超时在同一调用预算内退避 1s、2s，不叠加 SDK 重试。单次 HTTP 超时 20 秒；每问题总墙钟 75 秒，按剩余时间截断。每次 PG 执行有独立回滚边界。
3. 零行合法返回 empty，零分母返回 NULL 及原因；多表汇总与排名返回定义、稳定排序和来源。诊断问题只查授权的 v_diagnostics 或 v_checks。区分“报表披露”与“明细推算”；核对结果和必要假设在本地按条件渲染，使用真实 check_id。达不到语义或来源要求时返回可澄清字段和失败原因。
4. 本地为 trace_id 保存尝试序号、字典 hash、候选 SQL（受限审计）、解析判定、错误类别、真实执行 SQL、来源与耗时。每次纠正均重新授权、检索和验证；任何一次失败不产生可展示数字。

## 交付物

`src/chatbi/query/{longtail,results}.py`、`config/semantic/prompts.yaml`、`tests/test_s12.py`、`var/evidence/attempts.json`。

## 验收条件

1. `pytest -q tests/test_s12.py -k retry` 全绿；假模型依次给类型错误、未知列、合法查询，见 3 次调用和最终手算结果；连续不同可纠错失败在第 3 次结束，越权在第 1 次终止。
2. `pytest -q tests/test_s12.py -k egress` 检查每次模拟传输体中只有许可字典和脱敏问题，原始异常、上一轮 SQL、明细哨兵均 0 次出现；空结果、限时、无权限返回独立状态。
3. `chatbi ask-local --live --role boss '按工厂列出报工工时合计并排序'` 返回 longtail、非空结果、授权 SQL、单位及工作表来源；用同角色在同批次重放得到同表。无实连时记待验。

## 常见坑

数据库能执行只证明语法成立；来源、期间及分母仍需核对。回退到更宽字典、按旧题缓存结果或让模型补写数值都会破坏验收。

## 预计工作量与并行

2–3 小时。与 11 并行；该步 CLI 的 --role 仅本机测试工具可用。
