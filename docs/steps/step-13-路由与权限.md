# 13 路由与权限

## 目标

同一入口按本地身份、问题意图和可用证据分派，复合提问的各部分均有交代。

## 前置条件

11、12 路径能分别返回结果块。

## 输入

术语、签字模板能力矩阵、账号权限和完整问题；可选上一轮已授权的结构化筛选。

## 详细任务清单

1. 在 roles.yaml 记录主体→动作、域、最高密级、可外发字典集合及 PG 登录映射。boss 可查全部 POC 域并看审批允许的诊断，sales 只能查普通销售（不含成本/毛利及其他敏感字段），ops 只能查普通生产。employee 仅导入，无问数权。将相应列级投影、视图/列 SELECT 权限、样例和来源访问一起约束。数据读取与允许字典出域分别判断。客户端不提供角色或 DSN。
2. 规范规则顺序：认证/动作检查 → 本地识别资料请求、越权和时间条件 → 区分业务指标、清洗假设、比较及复合意图 → 抽取本地期间/筛选/分组 → 签字且支持的指标走模板，其余有来源的业务或诊断子问走长尾。缺签字、维度不支持或模板异常的签字计算给出澄清/不可用。普通组合比较可由本地汇合模板计算与其他来源，基础签字部分始终引用已签模板。仅关键词重合（如“表头中的销售额”）不构成签字指标请求。
3. 跨域请求先按所有子问联合鉴权；任何明确越权则整问拒绝，云调用和 SQL 执行均为零。缺字典/缺回款流水/资料请求给出具体范围，无法推断的比较期询问补充。支持一个问题最多 8 块，服务端按语义拆分；超限先求澄清。来源相容的子问共用一个查询或模板，75 秒为整问预算。
4. 追问仅保留同用户、同批次、同会话的指标/期间/维度/已绑定筛选，诸如“按工厂拆开”合并条件，“换成本季”替换期间；换话题清空，撤权后重查，过期会话提示重问。审计记录 request_id、路由依据、模板/字典版本和各块状态。

## 交付物

`src/chatbi/query/{router,policy,session}.py`、`config/roles.yaml`、`tests/test_s13.py`。

## 验收条件

1. `pytest -q tests/test_s13.py -k routes` 全绿；12 个签字同义问法 12/12 命中、至少 6 个自编长尾正确进入检索、资料问题和来源不足问题有明确状态；签字问法云调用 0。
2. `pytest -q tests/test_s13.py -k access` 全绿；员工问数、销售看成本、包含越权子问、撤权后复用历史四组全部拒绝；拒绝后网关和 SQL 调用计数为 0。
3. `pytest -q tests/test_s13.py -k context` 覆盖复合问题逐块回答、按月拆分、时间替换、换话题、不同用户会话隔离，断言来源、期间与块数。

## 常见坑

模板与长尾可以同时服务一个复合问题。对比某个错误汇总方法时应算出该方法的影响，同时标明哪一组数可用于经营决策。

## 预计工作量与并行

1.5–2.5 小时。路由夹具和会话测试可并行。
