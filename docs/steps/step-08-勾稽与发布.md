# 08 勾稽与发布

## 目标

用同一批次的独立源表复算财务关系，确认数据一致后再对外可见。

## 前置条件

07 staged 批次可查，未被线上视图引用。

## 输入

工作簿「数据字典与口径」及报表注，暂存、核准服务 SKU 分类、来源行账。

## 详细任务清单

1. 按下表建立具名规则。左右两侧各注明表、期间、金额单位、行过滤、聚合粒度和来源。每月可核则另跑 7、8、9 月，季末余额仅跑截止日。未取得左右证据标 missing 并阻发布。
   
   | 必检关系 | 过滤和精度 |
   |---|---|
   | 销售净额、销售成本各自对利润表，四类期间费用各自对利润表 | 保留红字；按记账金额，元 |
   | 营收－成本对毛利，利润总额－所得税对净利润 | 同期间；毛利无原始报表行可用销售明细毛利列复核 |
   | 资产总计对负债及权益总计，AR 原值减坏账对表列净额，AP 未付对表列应付 | 同一期末，AP 含税，不扣两次坏账 |
   | 成品＋材料＋在产品月末对资产负债表期末存货 | 只取期末月；同类库存按期初＋入－出核期末 |
   | 经营、投资、筹资及汇率影响对现金净变动；期初＋净变动对期末；期末对货币资金 | 以季度现金期初作起点，各项独立取数 |
   | 实际产量对合格＋不良；成品出库成本对实物销售成本 | 仅报工明细；销售成本剔除已确认服务 |
   | 目标表实绩对销售明细；采购不含税换元对原材料采购入库 | 销售比对同一范围；采购按披露精度处理尾差 |
2. 对元表记账合计用绝对差 ≤1 元；整数数量精确相等。采购等涉及逐行两位万元舍入，用工作簿注明的精度推导上界（每个独立舍入值最多 50 元，汇总值按其自身精度另计），报告实际差、行数和上界；不可放宽验收答案的 ±1 元。对与表注不符的源数据记录差异及责任人，先查清字段/范围；必检失败整批停在 staged/failed。
3. `chatbi reconcile` 生成 JSON 和人可读表，含左右值、差额、阈值、日期范围、状态、双方定位。`chatbi publish` 在锁内重新确认证据对应同一不可变批次、映射和规则版本；验证全通过才切 meta.current，写发布流水，同事务提交。`chatbi publish --restore BATCH` 可切回同数据集已验版。读请求在一个只读可重复读快照内完成。
4. 源报告引用的外部 validation_report.json 未随任务提供。以本机独立复算为证，不直接认领参考资料中校验次数。

## 交付物

`sql/reconcile/`、`src/chatbi/db/{reconcile,publish}.py`、`var/evidence/reconcile.json`、`var/evidence/reconcile.md`、`tests/test_s08.py`。

## 验收条件

1. `chatbi reconcile && chatbi publish && chatbi db inspect-batch` 全部成功；所有上表关系有双方来源且 failed=missing=0，当前指针等于报告批次，bi 视图能读到该版。
2. `pytest -q tests/test_s08.py -k mismatch` 在复制的合成批次将销售净额加 2 元；对应金额检查失败、发布非零、原当前版仍可读；删除对侧全部行也须失败。
3. `pytest -q tests/test_s08.py -k switch` 对两个合格小批次并发读写切版、重发和恢复，单次读取的全部事实与来源 batch_id 一致，恢复后行数及金额回到前版。

## 常见坑

空集合 SUM 的 NULL 不能填成两侧同为零后通过。服务成本、采购税额、年度期初、季末余额选择错误时应修数据口径。

## 预计工作量与并行

2–3 小时。三表规则与运营规则可并行。
