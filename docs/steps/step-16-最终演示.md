# 16 最终演示

## 目标

从一次重启开始演示可信模板、长尾、来源复算、拒绝与完整盲测，并可追溯每个结论。

## 前置条件

01–15 必需件齐备，实际签认完成，有实连密钥和已冻结运行包，验收者单独持有评测报告。

## 输入

锁文件、原件哈希、映射与模板签认、已发布批次、权限配置、真实请求和独立分数。

## 详细任务清单

1. `scripts/demo preflight` 核对包/工作簿/签字哈希、当前批次、socket 权限、网关探针、服务健康及隔离报告。重启 PG/BFF/网关，恢复同一批；重复加载同一工作簿，确保前后发布版和行数一致。全程记录时间和版本。无真实密钥时标 live_pending。
2. 现场依次操作：老板问月度合格产量（展示签字和 SQL，外呼计数无增长）；问工厂报工工时排名（真实长尾，打开来源）；追问切换维度；看一次小计产生的金额差异（带清洗诊断）；销售身份询问受限财务指标（403）；询问缺少流水的回款或工艺资料（返回范围/缺源说明）。挑一个结果用相同授权、批次和参数重放 SQL，再到原工作簿定位对应行或报表格。
3. 以受控替身重演一次自动纠错并标记 mock，与真实链路展示分别取证。验收者在锁定构建上启动一次完整盲测；若 15 的 live01 已在同一哈希、同一批次、同一模型配置运行，可直接验证该完整记录，避免只挑成功运行。不同构建用新 ID。留存按组分数、所有失败及问题单。报告、答卷不打入运行包。
4. `scripts/demo verify` 根据各步证据清单打印通过、失败、待验证和证据路径；产出不含标准答案的交接清单。区分可部署程序包、可复演的配置与验收者私有附件。

## 交付物

`scripts/demo`、`var/evidence/demo/{manifest.json,walkthrough.md,replay.json}`、`private-eval/runs/<id>/report.md`、`tests/test_s16.py`。

## 验收条件

1. `scripts/demo preflight && scripts/demo replay` 成功；清单指纹与当次包/批次一致，重导前后计数相同，重放列/值与网页一致，来源能定位表名和行/格。
2. `pytest -q tests/test_s16.py && scripts/demo verify` 在证据齐全时退出 0，逐项核对上列现场动作，至少一条 longtail 有真实网关请求，越权请求 DB/网关调用均为 0。任一假证据替代 live、缺失项或硬门槛失败均非零。
3. `python -m evaluator audit --dir private-eval --id live01 && python -m evaluator score --dir private-eval --id live01`（复跑时替换 ID）生成全部 40 题报告，等级 B 或 A、五维总分 ≥80 且验收规范的硬门槛全过，方记 POC 通过。

## 常见坑

只测一次网页成功不会覆盖重启、权限或盲测。展示 mock 输出时应在屏幕和清单显式标记。

## 预计工作量与并行

1–1.5 小时现场演示与复核，40 题真实模型耗时另计。
