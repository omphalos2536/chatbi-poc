# 15 隔离评测

## 目标

由独立验收者通过公开 API 自动跑满 40 题，将实际答案、五维得分和差异留在评分侧。

## 前置条件

14 接口冻结，真实运行时隔离已验证。评分器的开发者单独持有基准，完成此步后不携带答案上下文参与被测系统开发。

## 输入

仅评分进程读取 `refs/答案基准与清洗规则.md` 的第七、八节；评分配置、报告放 `private-eval/`。系统侧只读作为输入的单条自然语言题干。

## 详细任务清单

1. 实现 `python -m evaluator prepare` 逐个解析 Q1–Q40 的粗体题干、后续段落和 Markdown 表格，用 ID/序号防串题；检测缺/重复 ID。去掉“★陷阱”、分组、题号和粗体等评审标记，保留用户语义。验收者在私有 assertions.yaml 将每题必答子项绑定到别名、单位、期别、组键、排序、预期数/解释依据、适用维度和关键词组。基准中表格长短与题干不一致（如要求 Top5、只列部分结果）时，按已给项判、未覆盖项由验收者独立回读工作簿补证；记录补证与版本，禁止靠被测结果补全。只有定性说明时按其必要论点判，分开标识可复算但基准未列的数值。
2. 冻结运行包和私有断言哈希。`run` 对每题新建会话，取 boss 评测身份，串行 POST /api/ask，仅发 question；请求端超时 85 秒。记录原响应、状态、耗时、route、attempts、request_id，网络异常/空答留作失败，继续跑满；断点恢复只补没有响应记录的题，正式首跑和修复后复跑分开编号。禁止传答案、抽取出的预期关键词、题号或上一题反馈，停用答案缓存。独立保存仅含请求键的传输清单和每题题干哈希。
3. `score` 本地按列 ID/别名、分组键和期间匹配，不在整段文本搜索数字。金额统一元绝对误差 ≤1，比率换成百分点后 ≤0.01pp，计数与名次精确，万元/人、天、倍按基准披露的小数位比较（金额以元给出时始终按元容差）。对仅有舍入金额的基准先明确以何披露值比较或用原件补足精度并留证；不以百分比相对误差代替绝对误差。榜单按题干 N、实体和次序；同分同值组允许互换。遗漏、错位、反号、重复行或分母错误均记具体子项失败。
4. 五维分别占口径 35、清洗 30、数值 20、勾稽 10、解释 5。为每维生成冻结的适用断言清单；逐题逐维分值 = 已过条数 / 适用条数。维度总分 = 权重 × 该维所有适用题分值的均值；不适用标 N/A，要求每维至少一题。失败请求在所有适用维度取 0。口径匹配公式、单位或标签；清洗匹配实际批次的诊断/来源及计算；勾稽要求相符的两侧和真实通过的 check_id；解释要求命中必要概念及方向/归因，假设须标注。可用同义词组加结构化字段自动断言，歧义标 review 并保留原判，人工复核有署名、理由和证据。报告首轮自动分及裁定分。每题“正确”指所有必答数值/实体/必要口径与定性子项通过。
5. 输出 20 道基础、12 道分析、8 道陷阱的正确率，逐题五维、偏差、缺项、来源、路由与总分；列阻断项和验收等级（按验收规范）。输出仅评分侧可读的 JSON/Markdown，向开发方回传缺陷类别和合成复现，不回灌答案。

## 交付物

`evaluator/{__main__,prepare,run,score}.py`、`evaluator/tests/test_scoring.py`、`private-eval/{assertions.yaml,manifest.json,runs/}`。

## 验收条件

1. `python -m evaluator prepare --gold refs/答案基准与清洗规则.md --out private-eval && python -m evaluator validate --dir private-eval` 输出 40 个唯一题号、分组 20/12/8，全部必答项有类型、来源和适用维度；清单哈希可核对。
2. `pytest -q evaluator/tests/test_scoring.py` 全绿；用独立合成数据测试 ±1 元、±0.01pp 边界内外、负数、万元、错位名次、缺答、同义解释，五维加权手算值与脚本相同，响应失败不被跳过。
3. `python -m evaluator run --dir private-eval --id live01 --base http://127.0.0.1:8080 --auth var/run/boss.curl && python -m evaluator score --dir private-eval --id live01` 留下 `runs/live01/{responses.jsonl,report.json,report.md}`，含 40 个终态（HTTP 错误也有记录）；真实长尾记录能和网关 request_id 对上。评分产物完整和系统效果达标分别记录。
4. `scripts/serve probe-isolation && python -m evaluator audit --dir private-eval --id live01` 返回 blocked_reads=全部预定探针、unexpected_request_keys=0、gold_in_runtime=0；复评分相同响应与冻结断言，两次各维得分完全一致。

## 常见坑

四舍五入、汇总行与分项、仅有部分排名的基准会使子串匹配失真。评分进程拥有的工作目录、测试夹具、报告乃至失败反馈都要排除在运行包之外。

## 预计工作量与并行

2–3 小时实现评分器。私有断言可由第二位验收者按三组并行整理，每组另预算 1–2 小时；真实模型调用时间另计。
